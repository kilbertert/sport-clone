## 3. 需求概述
### 背景
现有精准体育系统已具备风险预警、人才储备、年级卡点和管理提示，但数据分散，缺少区域驾驶舱常见的排名、项目达标率、趋势和群体结构视图，管理者难以快速完成“发现问题、判断优先级、执行干预”的闭环。

### 核心需求
在不改变现有浅色管理后台视觉体系的前提下，重组精准体育系统驾驶舱，增加区域/学校排名、项目达标率、年级趋势、男女生比例，统一接入学校和年级筛选，并在各模块提供一句话优点/缺点摘要，底部形成按轻重缓急排序的智慧管理决策。

### 预期效果
管理者进入页面后可在单屏内掌握总体指标、重点风险、人才储备、结构趋势和待办动作；筛选口径一致，空数据明确提示，减少误判并提升决策执行效率。

## 4. 需求背景与目标
### 4.1 背景
参考区域平台驾驶舱的信息组织方式，当前页面需要从单纯的数据展示升级为面向管理决策的综合驾驶舱。演示数据必须保持真实口径边界，不直接冒充区域真实数据；筛选后无结果时不得显示伪造的 0 值或趋势。

### 4.2 目标
1. 将总览、风险、人才、排名、达标率、趋势、群体结构和决策模块集中在 `/precision` 页面。
2. 学校和年级筛选统一影响全部指标和图表，无数据时显示“暂无数据”。
3. 每个模块提供简洁的“优点/缺点”总结，底部决策按“立即处理 / 本周处理 / 规划跟进”排序。
4. 保持现有 React/Vite 技术栈，不新增第三方依赖，构建检查通过。

## 6. 业务逻辑
1. 页面默认使用“全域学校 / 全部年级”口径。
2. 用户改变学校或年级后，KPI、风险列表、人才图表、年级表、四项驾驶舱图表和决策摘要使用同一筛选口径刷新。
3. 筛选无匹配数据时保留模块标题和说明，内容区显示“暂无数据”，不得用默认数据覆盖。
4. 管理动作按立即处理、本周处理、规划跟进排序；每条决策包含建议动作和当前状态。

## 7. 功能详细说明
### 7.1 总览与筛选
#### 功能定位
提供驾驶舱入口指标和统一数据口径。
#### 产品规则
1. 支持学校、年级两个筛选条件。
2. 展示受伤风险、田径人才、网球队人才、核心卡点年级、数据覆盖率五项 KPI。
3. 每个模块标题下展示优点与缺点摘要。
#### 字段定义
| 字段名 | 字段类型 | 是否必填 | 说明 |
|---|---|---|---|
| school | string | 是 | 当前学校数据域 |
| grade | string | 是 | 当前年级数据域 |
| metricValue | number/string | 是 | 指标值或“--”空值 |
| insight | string | 是 | 模块优点/缺点摘要 |
#### 异常处理
- 无匹配数据：指标显示“--”，提示显示“暂无数据”。

### 7.2 区域概览图表
#### 功能定位
以图表补充区域驾驶舱视角，支持快速比较和趋势判断。
#### 产品规则
1. 展示区域/学校排名、项目达标率、年级达标趋势、男女生比例。
2. 图表仅使用当前系统数据；区域真实数据接入前不得使用参考截图数据冒充真实结果。
3. 图表在筛选变化后同步更新。
#### 字段定义
| 字段名 | 字段类型 | 是否必填 | 说明 |
|---|---|---|---|
| name | string | 是 | 学校、项目或年级名称 |
| value/pass | number | 是 | 排名分值、达标率或趋势值 |
| gender | string | 否 | 男女生分类 |
#### 异常处理
- 数据为空：图表区域显示“暂无数据”。

### 7.3 智慧管理决策
#### 功能定位
将指标和风险转化为分级可执行的管理动作。
#### 产品规则
1. 优先级固定为立即、本周、规划。
2. 每条决策包含问题、建议动作和状态。
3. 决策摘要随筛选口径变化，避免跨范围误导。
#### 字段定义
| 字段名 | 字段类型 | 是否必填 | 说明 |
|---|---|---|---|
| priority | enum | 是 | 立即 / 本周 / 规划 |
| action | string | 是 | 建议执行动作 |
| status | string | 是 | 当前闭环状态 |
#### 异常处理
- 决策所需数据为空：保留模块结构并显示“暂无数据”，不生成虚假建议。
