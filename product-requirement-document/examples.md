## 3. 需求概述

### 背景
当前用户在查询订单物流状态时，需要手动复制快递单号到第三方平台查询，操作流程繁琐，用户体验较差。用户在等待收货期间对物流状态有较高的关注度，实时便捷的物流查询是提升用户满意度的关键触点。

### 核心需求
在订单详情页集成物流信息展示功能，支持主流快递公司的实时物流查询，并增加物流状态变更推送通知，减少用户查询物流的操作成本。

### 预期效果
通过物流信息实时展示和主动推送，提升用户查询物流的便捷性，预计可减少 80% 的物流相关客服咨询，提升订单详情页的用户停留时长。

---

## 4. 需求背景与目标

### 4.1 背景
当前平台订单详情页仅展示快递公司和运单号，用户如需查看详细物流轨迹，需要手动复制单号前往快递公司官网或第三方查询平台。这一流程存在以下问题：
1. 操作路径长，需要跳出 App/小程序
2. 用户需要手动输入或粘贴单号，容易出错
3. 无法及时获取物流状态更新
4. 客服团队收到大量"查物流"类咨询，占用客服资源

### 4.2 目标
1. **用户体验目标**：在订单详情页内完成物流查询，操作步骤从 5 步减少到 1 步
2. **覆盖范围目标**：支持顺丰、京东、中通、圆通、韵达、申通等主流快递公司，覆盖 95% 以上订单
3. **时效性目标**：物流状态更新延迟控制在 5 分钟以内
4. **业务目标**：物流相关客服咨询量降低 50% 以上

## 6. 业务逻辑

### 6.1 业务流程图

```
用户下单 → 商家发货 → 系统接收物流单号 → 调用物流查询API
                                              ↓
用户查看物流 ← 展示物流信息 ← 解析物流数据 ← 获取物流轨迹
                                              ↓
用户收到推送 ← 发送推送通知 ← 物流状态变更 ← 订阅状态更新
```

### 6.2 流程说明

1. **发货同步**：商家发货后，系统将物流单号和快递公司信息同步至物流查询服务
2. **数据获取**：物流查询服务调用第三方 API 获取实时物流轨迹数据
3. **状态监控**：系统订阅物流状态变更事件，当状态更新时触发推送
4. **信息展示**：订单详情页展示最新物流状态和关键节点信息
5. **主动推送**：物流状态发生关键变更（已发货、派送中、已签收）时，向用户发送推送通知

## 7. 功能详细说明

### 7.1 订单详情页物流信息展示

#### 功能定位
在订单详情页提供物流信息的快捷查看入口，展示最新物流状态和关键节点，是用户查看物流信息的主要入口。

#### 产品规则
1. 仅对已发货订单展示物流信息模块
2. 物流信息模块默认展示最新一条物流轨迹
3. 点击模块可进入完整物流轨迹详情页
4. 物流状态按时间倒序排列，最新状态置顶
5. 已签收订单展示签收时间和签收人信息

#### 字段定义

| 字段名 | 字段类型 | 是否必填 | 说明 |
|--------|----------|----------|------|
| logistics_no | string | 是 | 物流单号 |
| logistics_company | string | 是 | 快递公司名称 |
| logistics_company_code | string | 是 | 快递公司编码 |
| status | string | 是 | 物流状态：待发货/已发货/运输中/派送中/已签收/异常 |
| latest_trace | object | 是 | 最新物流轨迹 |
| latest_trace.time | datetime | 是 | 轨迹时间 |
| latest_trace.content | string | 是 | 轨迹内容 |
| trace_list | array | 是 | 完整轨迹列表 |
| signed_time | datetime | 否 | 签收时间，已签收时必填 |
| signed_person | string | 否 | 签收人，已签收时必填 |

#### 业务定义
- **待发货**：订单已支付，商家未发货
- **已发货**：商家已发货，物流已揽收
- **运输中**：快件在运输途中
- **派送中**：快递员正在派送
- **已签收**：快件已被签收
- **异常**：物流异常，如滞留、退回等

#### 交互说明
- 物流信息模块位于订单状态下方
- 模块高度固定，展示最新一条轨迹的缩略信息
- 点击模块整体进入物流详情页
- 物流状态图标根据状态动态变化

#### 异常处理
- **物流查询失败**：展示"物流信息查询中，请稍后重试"，提供刷新按钮
- **物流单号无效**：展示"物流单号异常，请联系商家"
- **快递公司不支持**：展示"暂不支持该快递公司查询"

---

### 7.2 物流状态推送通知

#### 功能定位
通过消息推送主动告知用户物流状态变更，减少用户主动查询的频率，提升服务感知。

#### 产品规则
1. 仅对关键状态变更发送推送：已发货、派送中、已签收、异常
2. 用户可设置是否接收物流推送（默认开启）
3. 同一订单同一状态不重复推送
4. 推送消息点击可跳转至订单详情页

#### 字段定义

| 字段名 | 字段类型 | 是否必填 | 说明 |
|--------|----------|----------|------|
| order_id | string | 是 | 订单ID |
| push_type | string | 是 | 推送类型：logistics_shipped/logistics_delivering/logistics_signed/logistics_exception |
| title | string | 是 | 推送标题 |
| content | string | 是 | 推送内容 |
| jump_url | string | 是 | 跳转链接 |

#### 业务定义
- **已发货推送**：您的订单已发货，{快递公司} {单号}，点击查看物流详情
- **派送中推送**：您的订单正在派送中，快递员：{姓名} {电话}，请保持电话畅通
- **已签收推送**：您的订单已签收，签收人：{签收人}，期待您的评价
- **异常推送**：您的订单物流异常：{异常原因}，请联系商家或快递公司

#### 交互说明
- 推送消息以系统通知形式发送
- 点击推送消息跳转至对应订单详情页
- 在 App 内以消息中心形式聚合展示

#### 异常处理
- **推送失败**：记录失败日志，进入重试队列，最多重试 3 次
- **用户关闭推送**：尊重用户设置，不再发送物流类推送
