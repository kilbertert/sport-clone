## 3. 需求概述

### 背景
由于国家税务局新规定，目前入驻公司的远方智慧物流公司无法继续开具 6% 的物流辅助服务费发票，必须改为开具交通运输费用发票（税率 9%）。此类发票在调用百望开票系统时，要求必须传输运输车牌号、起运地、到达地和交通运输工具等字段，而现有功能不支持这些字段的维护和传输，需要基于现有功能进行改造。

### 核心需求
对 OMS 系统发票管理功能进行改造，支持交通运输费用发票的开具，包括运输车牌号维护、起运地/到达地自动获取、交通运输工具字段填充等功能。

### 预期效果
满足国家税务局新规要求，确保远方智慧物流公司能够正常开具 9% 税率的交通运输费用发票，保障供应商结算流程合规顺畅。

---

## 4. 需求背景与目标

### 4.1 背景
当前平台存在以下问题和合规风险：

1. **政策合规风险**：国家税务局新规要求物流辅助服务费与交通运输服务必须区分开票，远方智慧物流公司作为入驻平台的物流企业，需要按照实际业务类型开具 9% 税率的交通运输费用发票

2. **系统功能缺失**：现有 OMS 发票管理功能仅支持 6% 物流辅助服务费发票的开具，缺少交通运输费用发票必需的字段（运输车牌号、起运地、到达地、交通运输工具）

3. **百望开票接口限制**：调用百望开票系统开具交通运输费用发票时，上述字段为必填项，缺失将导致开票失败

4. **供应商结算受阻**：无法开具合规发票将直接影响供应商的结算和税务处理

### 4.2 目标

1. **合规目标**：支持开具符合国家税务局规定的 9% 税率交通运输费用发票
2. **功能目标**：完成 OMS 发票管理模块改造，支持运输车牌号维护、起运地/到达地自动获取、交通运输工具字段配置
3. **数据准确性目标**：确保起运地、到达地等字段数据准确，与业务实际一致
4. **用户体验目标**：改造后的功能操作流程简洁，不增加供应商额外操作负担

## 6. 业务逻辑

### 6.1 业务流程图

```
供应商进入OMS → 发票管理 → 基础信息管理
                    ↓
            维护运输车牌号（新增）
                    ↓
            选择待开票账单 → 申请开票
                    ↓
            系统获取：
            - 起运地：智慧物流营业执照注册地
            - 到达地：账单最后一笔运输收货地址
            - 交通运输工具：固定值"公路运输"
                    ↓
            调用百望开票接口（含新增字段）
                    ↓
            发票开具成功/失败
```

### 6.2 流程说明

1. **基础信息维护**：供应商在 OMS 发票管理-基础信息管理中维护运输车牌号信息
2. **发票申请**：供应商选择待开票账单，发起发票申请
3. **数据获取**：系统自动获取以下信息：
   - **起运地**：从智慧物流营业执照注册地获取省市区信息
   - **到达地**：从账单内最后一笔运输订单的收货地址提取省市区
   - **交通运输工具**：固定填充为"公路运输"
4. **开票调用**：调用百望开票接口时，传入新增必填字段
5. **结果反馈**：返回开票成功或失败信息

## 7. 功能详细说明

### 7.1 基础信息管理-运输车牌号维护

#### 功能定位
在 OMS 发票管理基础信息管理中增加运输车牌号维护功能，为开具交通运输费用发票提供必需的车辆信息。

#### 产品规则
1. 运输车牌号为开具交通运输费用发票的必填字段
2. 一个供应商可维护多个运输车牌号（支持多车辆业务场景）
3. 车牌号格式校验：符合中国车牌号规范（如：粤A12345、京A12345等）
4. 默认车牌号：可设置一个默认车牌号，开票时自动填充
5. 历史数据：历史已开票数据不强制要求补充车牌号

#### 字段定义

| 字段名 | 字段类型 | 是否必填 | 说明 |
|--------|----------|----------|------|
| vehicle_plate_id | string | 是 | 车牌号记录ID，系统生成 |
| supplier_id | string | 是 | 供应商ID |
| plate_number | string | 是 | 车牌号码，如"粤A12345" |
| is_default | boolean | 否 | 是否为默认车牌号 |
| vehicle_type | string | 否 | 车辆类型，如"货车"、"厢式货车" |
| create_time | datetime | 是 | 创建时间 |
| update_time | datetime | 是 | 更新时间 |

#### 业务定义
- **车牌号格式**：支持普通车牌（蓝牌）、新能源车牌（绿牌）、港澳车牌等格式
- **默认车牌号**：同一供应商只能设置一个默认车牌号
- **使用场景**：开票时优先使用默认车牌号，用户可手动切换

#### 交互说明
- 在基础信息管理页面新增"运输车牌号"卡片/区域
- 展示已维护的车牌号列表，支持增删改查
- 提供"设为默认"操作按钮
- 新增/编辑车牌号时进行格式校验

#### 异常处理
- **车牌号格式错误**：提示"请输入正确的车牌号码格式"
- **重复车牌号**：提示"该车牌号已存在"
- **删除默认车牌号**：提示"请先设置其他默认车牌号后再删除"

### 7.2 发票开具-交通运输费用发票改造

#### 功能定位
改造现有发票开具功能，支持开具 9% 税率的交通运输费用发票，并自动填充百望开票所需的运输相关字段。

#### 产品规则
1. 发票类型选择：增加"交通运输费用"选项（税率 9%）
2. 发票类型与字段关联：选择交通运输费用时，必须填写运输相关字段
3. 字段自动填充：起运地、到达地、交通运输工具字段系统自动获取
4. 字段手动确认：自动填充的字段展示给用户确认，支持手动修改
5. 车牌号选择：从已维护的车牌号列表中选择
6. 开票校验：交通运输费用发票必须填写所有运输相关字段才能提交

#### 字段定义

| 字段名 | 字段类型 | 是否必填 | 说明 |
|--------|----------|----------|------|
| invoice_type | string | 是 | 发票类型：transportation（交通运输费用）/ logistics（物流辅助服务） |
| tax_rate | number | 是 | 税率：交通运输费用为 9%，物流辅助服务为 6% |
| vehicle_plate_number | string | 是 | 运输车牌号 |
| departure_province | string | 是 | 起运地-省 |
| departure_city | string | 是 | 起运地-市 |
| departure_district | string | 否 | 起运地-区 |
| arrival_province | string | 是 | 到达地-省 |
| arrival_city | string | 是 | 到达地-市 |
| arrival_district | string | 否 | 到达地-区 |
| transport_tool | string | 是 | 交通运输工具，固定值"公路运输" |
| invoice_amount | number | 是 | 开票金额 |
| bill_ids | array | 是 | 关联账单ID列表 |

#### 业务定义
- **起运地获取逻辑**：
  1. 查询智慧物流公司营业执照注册地
  2. 解析注册地省市区信息
  3. 填充到起运地字段
  
- **到达地获取逻辑**：
  1. 查询账单关联的运输订单列表
  2. 取最后一笔运输订单的收货地址
  3. 解析收货地址省市区信息
  4. 填充到到达地字段
  
- **交通运输工具**：固定为"公路运输"，不支持修改

#### 交互说明
- 发票类型选择后，动态展示对应的税率和必填字段
- 选择"交通运输费用"时，展开运输信息区域
- 车牌号下拉选择，默认选中默认车牌号
- 起运地、到达地自动填充后展示，用户可点击修改
- 交通运输工具展示为只读文本"公路运输"
- 提交开票前校验所有必填字段

#### 异常处理
- **未维护车牌号**：提示"请先维护运输车牌号信息"，引导至基础信息管理
- **起运地获取失败**：提示"起运地信息获取失败，请手动填写"，开放手动输入
- **到达地获取失败**：提示"到达地信息获取失败，请手动填写"，开放手动输入
- **百望开票失败**：展示具体错误信息，支持重新提交

### 7.3 百望开票接口改造

#### 功能定位
扩展百望开票接口调用，支持传输交通运输费用发票所需的额外字段。

#### 产品规则
1. 根据发票类型动态组装接口参数
2. 交通运输费用发票需传输运输相关字段
3. 物流辅助服务发票保持现有接口调用方式
4. 接口返回结果处理逻辑保持不变

#### 接口参数扩展

**交通运输费用发票新增参数：**

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| vehiclePlateNumber | string | 是 | 运输车牌号 |
| departureProvince | string | 是 | 起运地-省 |
| departureCity | string | 是 | 起运地-市 |
| departureDistrict | string | 否 | 起运地-区 |
| arrivalProvince | string | 是 | 到达地-省 |
| arrivalCity | string | 是 | 到达地-市 |
| arrivalDistrict | string | 否 | 到达地-区 |
| transportTool | string | 是 | 交通运输工具 |

#### 业务定义
- **接口路由**：根据发票类型选择不同的百望开票接口或参数模板
- **字段映射**：将 OMS 系统字段映射为百望接口所需字段格式
- **错误处理**：百望接口返回错误时，解析错误信息并展示给用户
