# 班级体质健康分层教学闭环

## Problem Statement

体育教师需要以班级为单位查看体质问题，而不是逐个查看学生。当前系统已有分层教学、速度大课间、家校协同和报告能力，但缺少统一的班级诊断入口，无法把有效体测数据转成问题占比、能力分组、风险等级和可执行方案。

## Solution

改造现有分层教学页面，以班级为唯一分析单位。教师选择学校、年级、班级和测试批次后，系统按有效测试样本识别五类问题，展示人数、占比、影响项目和严重程度；同时生成能力分组与风险等级。教师可以调整所有结果并填写原因，确认后一次生成体育课计划、大课间计划、分层家庭作业和班级分析报告，再分别同步到现有模块。同步不等于发布，复测后回到同一班级形成前后对比。

## User Stories

1. As a 体育教师, I want to 选择学校、年级、班级和测试批次, so that 我能在班级维度开始分析。
2. As a 体育教师, I want to 查看班级学生数、有效测试人数、覆盖率和最近测试时间, so that 我知道分析样本是否足够。
3. As a 体育教师, I want to 查看五类体质问题, so that 我能快速判断班级主要短板。
4. As a 体育教师, I want to 看到每类问题的有效样本数、影响人数和占比, so that 问题结论有数据依据。
5. As a 体育教师, I want to 看到问题影响的具体项目, so that 我能把问题连接到教学内容。
6. As a 体育教师, I want to 看到正常、轻度、关注和重点干预等严重程度, so that 我能安排处理优先级。
7. As a 体育教师, I want to 查看优势组、提升组、基础组, so that 我能安排分层课堂。
8. As a 体育教师, I want to 同时查看正常、关注、重点干预风险等级, so that 我不会把能力弱和训练风险混为一谈。
9. As a 体育教师, I want to 修改问题标签和严重程度, so that 我能修正系统与实际教学观察不一致的结果。
10. As a 体育教师, I want to 调整学生能力分组, so that 我能结合课堂实际组织教学。
11. As a 体育教师, I want to 修改训练动作、组数和强度, so that 方案符合场地和班级情况。
12. As a 体育教师, I want to 添加教师备注和调整原因, so that 后续复盘知道为什么修改。
13. As a 体育教师, I want to 在高风险学生被调整到高强度组时进行二次确认, so that 风险不会被无意覆盖。
14. As a 体育教师, I want to 在覆盖率不足时只预览方案, so that 不会用不完整数据正式发布。
15. As a 体育教师, I want to 一次生成体育课训练计划, so that 班级问题能落到课堂动作。
16. As a 体育教师, I want to 一次生成大课间分层计划, so that 年级或班级训练能在大课间执行。
17. As a 体育教师, I want to 按学生分组生成 3—5 份家庭作业, so that 家长收到与能力层级匹配的训练内容。
18. As a 体育教师, I want to 生成班级分析报告, so that 我能汇报问题、方案和后续复测安排。
19. As a 体育教师, I want to 分别同步四类成果到现有模块, so that 原有教学、家校和报告流程可以复用。
20. As a 体育教师, I want to 同步后仍需在目标模块确认发布, so that 草稿不会未经审核直接进入课堂或家长端。
21. As a 体育教师, I want to 查看系统生成、教师调整、教师确认、已同步、已发布、待复测、已复测状态, so that 我能知道方案所处阶段。
22. As a 体育教师, I want to 复测后比较问题占比和关键指标变化, so that 我能判断干预是否有效。
23. As a 学校管理员, I want to 查看班级完整学生姓名和指标, so that 我能支持学校层面的教学管理。
24. As a 区域管理者, I want to 查看授权范围内的班级汇总结果, so that 我能掌握执行情况而不越权修改教师方案。

## Implementation Decisions

- 以现有分层教学页面作为唯一班级分析入口，不新建独立入口。
- 分析粒度只支持班级；首期不开放年级、全校、区域作为教师分析对象。
- 问题占比分母采用对应项目有有效测试数据的学生数，并同时展示覆盖率。
- 五类问题为速度能力不足、下肢刚性或爆发力不足、柔韧性不足、协调性或稳定性不足、疲劳或风险偏高。
- 触发条件综合问题占比和同年级参考值；首期阈值为 `<10%` 正常、`10%—19.9%` 轻度、`20%—29.9%` 关注、`≥30%` 重点干预，并标明为演示口径。
- 能力分组与风险等级分开：优势/提升/基础组；正常/关注/重点干预。
- 教师可调整问题标签、严重程度、学生分组、动作、组数、强度和备注；保留系统建议值、教师最终值、原因、时间和操作者。
- 高风险学生被调入高强度组必须二次确认并记录原因。
- 覆盖率 `≥80%` 才允许确认和发布；`60%—79.9%` 仅允许预览；低于 `60%` 显示数据不足。
- 教师确认后生成体育课、大课间、分层家庭作业、班级报告四类草稿；家庭作业按学生分组生成 3—5 份。
- 同步与发布分离：同步写入目标模块草稿，发布必须在目标模块再次确认。
- 报告默认可展示班级全部学生姓名和指标，但仍受教师/学校管理员权限控制；对外汇报应使用汇总口径。
- 优先复用现有 `/teaching`、`/recess`、`/home-school` 和报告导出能力；不新增依赖。

## Testing Decisions

- 只测试用户可观察行为：筛选结果、问题占比、分组调整、二次确认、生成/同步/发布状态和复测对比。
- 主要测试 seam 是 `/teaching` 页面及其与现有目标模块的同步边界。
- 覆盖正常数据、无数据、低覆盖率、缺少单项指标、高风险调整和教师确认等场景。
- 使用仓库现有 Playwright QA 脚本风格验证桌面端和移动端页面；不测试具体 React 组件实现细节。
- 业务判定函数如抽取为独立模块，应补充最小单元测试，重点覆盖阈值边界和有效样本分母。

## Out of Scope

- 不新增区域或全校教师分析视角。
- 不实现医疗诊断、伤病结论或自动医疗建议。
- 不在本期接入真实后端数据库、消息服务或外部 AI 模型。
- 不在分析页直接向家长端发布家庭作业。
- 不实现逐学生独立生成家庭作业，首期按 3—5 个能力分组生成。
- 不改变其他页面独立使用时的既有功能。

## Further Notes

- 当前仓库主要使用演示数据和浏览器状态保存，正式规则、权限和复测闭环需要后端化。
- 报告中学生姓名和指标属于敏感数据，导出和展示必须遵循数据域权限。
- 该需求对应截图反馈“教师维度看班级、看年级、不看个体”；本规格已将教师实际分析对象收敛为班级。
