# ADR-0001：LLM 选型与文献检索的合规边界

## 状态

已接受

## 日期

2026-08-24

## 背景

当前系统包含科研分析、AI 写作和运动能力分析场景。学生体测和风险信息具有敏感性；文献平台的元数据、摘要和全文具有不同的访问与再利用权限。需要在首期产品中明确 AI 数据出域和文献接入边界。

## 决策

1. 学生敏感数据不得发送到第三方模型 API。涉及个人的风险判断先由确定性规则或受控服务完成，模型只接收脱敏、聚合后的上下文。
2. LLM 选型优先比较中文能力、私有化部署、工具调用、成本和审计能力；当前推荐先评估 Qwen 系列本地部署作为主候选，托管模型仅用于脱敏数据的质量对照，不在未评估前锁定供应商。
3. 首期文献检索只接入 Crossref、OpenAlex、PubMed 等开放或公开文献元数据接口。
4. 首期保存标题、作者、DOI、摘要（按来源许可）、来源、许可证和原文链接；不默认下载、缓存或再分发封闭全文。
5. CNKI、万方、维普、Web of Science、Scopus 等商业库必须在取得机构授权或正式 API 合同后单独接入，并按合同限制访问、缓存和展示。

## 影响

- 需要服务端代理、密钥管理、脱敏和审计，不能把模型密钥放在浏览器端。
- 报告生成必须保留来源、DOI、检索时间和人工确认状态。
- 真实全文 RAG 延后到许可证明确且技术授权完成后。

## 替代方案

- 直接把学生数据发送给通用模型：开发快，但无法满足当前隐私边界，否决。
- 爬取并自建商业文献全文库：版权、条款和维护风险过高，否决。
- 先自建模型：成本和运维复杂度不匹配当前验证阶段，暂不采用。
