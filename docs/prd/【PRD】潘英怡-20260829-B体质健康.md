## 3. 需求概述

### 背景

体育教师需要以班级为单位了解学生体质共性问题，而不是逐个查看学生后再手工汇总。当前系统已有分层教学、速度大课间、家校协同、学生分析和报告导出能力，但缺少统一的班级诊断、教师确认和跨模块成果同步流程。

### 核心需求

将“分层教学”升级为班级体质健康分析入口。教师选择学校、年级、班级和测试批次后，系统按有效样本识别五类问题，展示人数、占比、影响项目和严重程度；同时生成能力分组与风险等级。教师可调整并确认结果，随后生成体育课、大课间、分层家庭作业和班级分析报告四类草稿，再分别同步到既有模块。

### 预期效果

将教师工作方式从“逐个看学生”转为“先看班级问题、再组织分层干预”。问题判断有明确样本口径，教师保留最终调整权，方案生成与正式发布分离，后续可通过复测形成效果对比。

## 6. 业务流程

```text
选择学校 / 年级 / 班级 / 测试批次
  → 校验有效样本与数据覆盖率
  → 识别五类体质问题及严重程度
  → 形成能力分组与风险等级
  → 教师调整并填写原因
  → 教师确认
  → 生成四类成果草稿
  → 分别同步到目标模块
  → 目标模块再次确认发布
  → 执行与复测
  → 对比前后变化
```

## 7. 功能详细说明

### 7.1 班级选择与有效样本

教师在分层教学页面选择学校、年级、班级和测试批次。页面展示班级学生数、有效样本数、数据覆盖率和当前方案状态。每项问题的占比分母使用对应项目有效测试人数；没有项目数据时显示“该维度数据不足”。

覆盖率规则：`≥80%` 可确认和发布，`60%—79.9%` 仅预览，`<60%` 显示数据不足并禁止正式方案确认。

### 7.2 五类体质问题诊断

系统将班级数据归类为：速度能力不足、下肢刚性或爆发力不足、柔韧性不足、协调性或稳定性不足、疲劳或风险偏高。每项显示影响人数、有效样本、占比、影响项目、严重程度和系统判定。

首期演示阈值：`<10%` 正常、`10%—19.9%` 轻度、`20%—29.9%` 关注、`≥30%` 重点干预；同时结合同年级参考值，任一条件满足即可触发问题清单。

### 7.3 能力分组与风险分层

能力分组为优势组、提升组、基础组，用于安排课堂和大课间；风险等级为正常、关注、重点干预，用于控制训练负荷和复核顺序。两者独立展示，高风险学生不会因能力较强自动进入高强度方案。

### 7.4 教师调整与风险保护

教师可以调整问题标签、严重程度、学生能力分组、训练动作、组数、强度和备注。系统保留系统建议值、教师最终值、调整原因、调整时间和调整人。

当教师将重点干预学生调整到优势组时，页面要求二次确认和调整原因；取消确认不保存。班级体育教师和学校管理员可确认，区域管理者仅查看授权范围汇总。

### 7.5 四类成果生成与同步

教师确认后生成四类草稿：

1. **体育课训练计划：** 分组、动作、组数、强度和课堂安排。
2. **大课间分层计划：** 分区、节奏、场地和训练流程。
3. **分层家庭作业：** 按 3—5 个能力组生成家庭训练草稿。
4. **班级分析报告：** 班级信息、覆盖率、问题占比、对应方案和复测建议。

同步只写入目标模块草稿，不等于发布。大课间和家校协同页面会展示已同步草稿，并要求教师在目标模块再次确认发布；家庭作业不会从分析页自动发送给家长。

### 7.6 状态与复测

状态流转为：

```text
系统生成 → 教师调整 → 教师确认 → 已同步 → 已发布 → 待复测 → 已复测
```

当前已实现前四个状态及目标模块确认入口；“已发布”后的真实执行记录、测试批次持久化和复测前后对比属于后续完善范围。

## 8. 数据权限与隐私

1. 班级体育教师和学校管理员可查看授权范围内的学生姓名和指标。
2. 班级报告可包含学生姓名和指标，但导出必须继承数据域权限。
3. 对外汇报和区域展示默认使用汇总人数与比例。
4. 家长端只能查看本人学生和已发布任务。

## 9. 验收标准

1. 教师选择班级后可查看学生数、有效样本、覆盖率和测试批次。
2. 五类问题均展示人数、占比、影响项目和严重程度。
3. 缺少项目数据时显示“该维度数据不足”，不推断结果。
4. 能力分组与风险等级独立展示，教师可调整并保留原因。
5. 高风险学生调整到优势组时必须二次确认。
6. 覆盖率低于 80% 时只允许预览，不允许确认和发布。
7. 教师确认后可生成四类成果草稿。
8. 同步不等于发布，目标模块必须再次确认。
9. 桌面端和移动端页面无水平溢出。
10. 当前演示数据和演示阈值有明确标识。
